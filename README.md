# Coworking Nearby

Русский Telegram-бот: ближайшие активные коворкинги из локальной подборки владельца, оценка и описание из каталога, три маршрутные ссылки Яндекс Карт. Поддержаны `/start`, `/help`, геопозиция кнопкой или вложением, в том числе до `/start`. Выбранная точка не доказывает присутствие пользователя. Venue принимается как одна точка; исходная live location запускает один подбор, изменения не отслеживаются. В группе бот направляет в личный чат.

## Быстрый запуск через Docker

Нужны Docker с Compose и работающий daemon. Выполняйте команды из корня проекта. Не запускайте несколько poller с одним токеном.

Рабочий `data/coworkings.json` сейчас содержит `[]`: это корректный пустой каталог, бот ответит «В подборке пока нет коворкингов». `examples/coworkings.synthetic.json` — отдельные вымышленные данные для offline-проверки, они не подставляются автоматически.

Соберите образ только из явного разрешённого списка; не используйте `docker build .`. Архив не включает `.env`, окружение разработки и planning artifacts:

```sh
python3 -c 'import sys,tarfile; from pathlib import Path; t=tarfile.open(fileobj=sys.stdout.buffer,mode="w|",format=tarfile.USTAR_FORMAT); paths=[Path("Dockerfile"),Path("requirements.lock"),*sorted(Path("coworking_nearby").glob("*.py")),Path("data/coworkings.json")]; [t.add(p,arcname=str(p),recursive=False) for p in paths]; t.close()' | docker build -t coworking-nearby:local -
docker run --rm --network none coworking-nearby:local python -m coworking_nearby.catalog
```

Создавайте `.env` только если его ещё нет. Следующая команда использует exclusive create и никогда не перезапишет существующий файл:

```sh
python3 -c 'import os; fd=os.open(".env", os.O_WRONLY|os.O_CREAT|os.O_EXCL, 0o600); os.write(fd, open(".env.example", "rb").read()); os.close(fd)'
```

Если `.env` уже существует, сохраните его и редактируйте локально. Вставьте токен в `BOT_TOKEN` в локальном редакторе, не в чат, исходники или shell-команду. Не выводите `.env` и resolved `docker compose config`. Шаблон `.env.example` оставлен с пустым токеном. Compose читает `.env` локально для окружения контейнера; секрет не входит в build context или образ.

```sh
docker compose config --quiet
docker compose up -d
docker compose stop
```

Образ работает от UID 10001, не публикует порты; каталог примонтирован как read-only **директория**, чтобы атомарная замена файла была видна при перезапуске. Приложение читает snapshot при старте; runtime не меняет каталог. Grace period 20 секунд покрывает кооперативное завершение приложения до 16 секунд. Некооперирующие зависимости не имеют гарантии жёсткого времени завершения.

## Токен и BotFather

Если токен у вас уже есть, оставьте его локально; повторное создание бота не требуется. Для нового бота откройте [официальный BotFather](https://t.me/BotFather), отправьте `/newbot`, выберите отображаемое имя и свободный username, заканчивающийся на `bot`. Доступность конкретного username здесь не проверяется. Сохраните полученный токен как пароль. Инструкция: [Telegram: Obtain Your Bot Token](https://core.telegram.org/bots/tutorial#obtain-your-bot-token). При раскрытии токена отзовите его через BotFather.

## Конфигурация

| Переменная | Значение по умолчанию | Контракт |
|---|---|---|
| BOT_TOKEN | нет | обязательный непустой токен |
| CATALOG_PATH | data/coworkings.json | путь внутри процесса/контейнера |
| RESULTS_LIMIT | 3 | ровно одна ASCII цифра 1–5 |
| LOG_LEVEL | INFO | CRITICAL/FATAL/ERROR/WARNING/WARN/INFO/DEBUG/NOTSET |

LOG_LEVEL меняет только порог безопасных событий: queue wait — DEBUG, start — INFO, stop/warning — WARNING, fail — ERROR. При DEBUG/NOTSET queue wait записывается в миллисекундах, с насыщением 86 400 000; это время от атомарного admission до начала worker, отдельно от service deadline 90 секунд. Счётчик count ограничен 0–64. События не содержат chat/user/source id, координаты, URL, токен или исходные исключения. Сырые логи SDK, root, warnings и loop подавляются до форматирования при каждом уровне. Ранние ошибки конфигурации используют безопасный INFO-порог до применения настроек.

## Вариант с установленным Python

Нужен именно Python 3.12.15; установка интерпретатора зависит от системы. Из корня проекта:

```sh
python3.12 -c 'import sys; assert sys.version_info[:3] == (3,12,15)'
python3.12 -m venv .venv
.venv/bin/python -m pip install --index-url https://pypi.org/simple --require-hashes -r requirements.lock
.venv/bin/python -m coworking_nearby.catalog data/coworkings.json
```

Приложение на host **не загружает `.env` автоматически**. Для локального файла, содержащего только доверенные shell-совместимые присваивания, явно экспортируйте настройки без echo и tracing; не source чужие файлы:

```sh
(set +x; set -a; . ./.env; set +a; exec .venv/bin/python -m coworking_nearby)
```

Остановка — Ctrl-C или SIGTERM. Async API `run()` после единого cleanup пробрасывает отмену; CLI завершает штатную отмену кодом 0, ошибку cleanup — ненулевым кодом. Ошибка config/каталога останавливает запуск до polling; демо не заменяет отсутствующие данные.

## Подготовка и обновление каталога

Одна запись — один реальный филиал. Владелец обязан проверить соответствие названия, полного адреса с **городом и номером дома**, широты/долготы и ссылки одному месту. Валидатор подтверждает синтаксис, а не реальные факты, качество оценки или существование страницы.

JSON — UTF-8 массив без BOM и повторяющихся ключей. Обязательны `id` (уникальный, до 64 символов), `name` (до 150), `address` (до 250), `latitude` (конечное число −90…90), `longitude` (−180…180). Строковые числа и boolean для координат запрещены. Optional: `active` boolean (default true), `yandex_maps_url`, `short_review` (до 200, одна-две фразы владельца), `description` (до 500), `rating_text` (до 50), `rating_source` (`catalog` по умолчанию либо `yandex`), `rating_checked_at` и `updated_at` (YYYY-MM-DD). Неизвестные поля запрещены. Все записи, включая inactive, проверяются целиком; один дефект блокирует загрузку.

Внешние пробелы строк удаляются; нормализация не исправляет адреса. Nullable optional строки допускают null/пустоту; `active` и `rating_source` null не допускают. Для непустой оценки `yandex` обязательны дата проверки и URL. URL — абсолютный HTTPS на exact yandex.ru/yandex.com с `/maps` или `/maps/…`, без userinfo, поддоменов, управляющих символов и неоднозначного кодирования; разрешён только явный порт 443. Валидатор не открывает ссылки и не извлекает координаты из адреса, `ll` или shortlink.

Проверьте candidate файл до замены, например:

```sh
docker run --rm --network none --mount type=bind,src="$PWD/data",dst=/candidate,readonly coworking-nearby:local python -m coworking_nearby.catalog /candidate/coworkings.next.json
```

После проверки владельцем атомарно замените файл в той же директории и перезапустите единственный экземпляр:

```sh
mv data/coworkings.next.json data/coworkings.json
docker compose restart bot
```

Сохраняйте совместимую пару образа и проверенного каталога для rollback. Остановите неудачный экземпляр, восстановите пару, снова проверьте каталог и запустите один poller. Если безопасной пары нет — оставьте остановленным. Для host также нужен перезапуск процесса.

## Поведение и ограничения

Выбор — только active, Haversine по прямой, затем id при равенстве; нет фильтра города/радиуса и сортировки по рейтингу. Default 3 результата, максимум 5. Оценки и тексты берутся у владельца: «Оценка из списка» либо сохранённый «Рейтинг Яндекс Карт» с датой проверки. Нет live рейтингов, автоматически придуманных отзывов и обновления данных.

Кнопки «Пешком», «Транспорт», «На машине» открывают Яндекс Карты с началом в выбранной точке и концом в координатах филиала. Время и путь рассчитывает Яндекс после открытия пользователем; бот не использует Yandex API и не обращается к сайту организации. Расстояние в карточке приблизительное по прямой, не длина дороги и не время поездки.

Один чат обслуживается последовательно, разные чаты изолированы. В памяти максимум 64 принятых запроса, 8 на чат включая активный; перегрузка тормозит ingress. Очередь недолговечна: crash/restart может потерять незавершённое; нет exactly-once доставки. Отправки привязаны к исходному сообщению; при удалении источника доставка останавливается. После неопределённой сетевой ошибки повтора нет; частичная выдача возможна. Только подтверждённый 429 допускает один повтор текущего сообщения в общем бюджете ожиданий 15 секунд. Нет гарантии доставки произвольного неограниченного URL организации: AC-15/AX-05/NFR-06 остаются с платформенным ограничением до отдельного решения владельца.

Координаты поиска используются временно; бот не ведёт историю поиска и не отслеживает live location. Заявки и минимальный реестр пользователей хранятся в локальной SQLite. Это не удаляет сообщения и URL из Telegram или истории браузера и не обещает физическое обнуление RAM. Нет scraping, бронирования, наличия мест, цен, HTTP listener, webhook или платных сервисов.

## Проверка перед полезным live запуском

Offline результаты и ограничения приведены в [docs/verification.md](docs/verification.md). Для dev-проверки установите `requirements-dev.lock` с `--require-hashes`, затем `PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -q`. Сетевой socket guard остаётся включённым; Docker-проверки выполняются отдельно.

До полезного live запуска нужны локальный настоящий токен, реальные записи, проверенные владельцем, и ручная проверка: отправить **две разные точки**, для одного результата **каждой** открыть **все три режима**, проверить начало, конец и режим в браузере. Такие live проверки здесь не выполнялись. Offline тесты не доказывают принятие Telegram всех кнопок/URL и не являются независимой Guardian/Proof сертификацией. ## Предложения мест и администраторы

Для включения заполните локальный `ADMIN_IDS` числовыми Telegram ID администраторов через запятую и задайте `STATE_PATH=state/community.sqlite3`. Не публикуйте `.env` и базу пользователей. При пустом `ADMIN_IDS` остаётся базовый поиск. Каждый модератор должен сначала открыть бота и отправить `/start`, чтобы Telegram разрешил уведомления.

Кнопка «➕ Предложить место» и `/suggest` запускают заявку по полям каталога; `/cancel` отменяет ввод. `/myid` показывает собственный Telegram ID. Только настроенным администраторам доступны `/pending` для очереди модерации и `/users` для просмотра пользователей. Одобрение одним администратором публикует место в поиске без изменения исходного JSON. В реестре появляются только пользователи, взаимодействовавшие с этой версией бота; прошлые пользователи недоступны Telegram Bot API.

Compose сохраняет SQLite в приватном томе `community_state`; не удаляйте его при обновлении. Для резервной копии остановите единственный poller и сохраните том с ограниченным доступом; восстановление выполняйте до запуска бота. Ручную проверку формы, уведомлений всех администраторов и одобрения нужно выполнить в Telegram.
